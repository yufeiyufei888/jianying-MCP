# 原生验收：全新安装从未验收开始

这里测试技术兼容性，不重新剪辑正式 Vlog，不用他人的验收记录。只有明确获准创建**独立测试副本**后才运行 canary 脚本。用户可以手工操作剪映；agent 操控界面需单独授权。后台写入时剪映必须彻底退出，不自动关闭窗口。

## 先决条件

1. `doctor` 已确认正确配置、11.5.0.14471、固定格式转换程序和原片引用后端；11 项引用回归通过。先明确配置 `worker_python` 为选定已有解释器，避免 SDK 环境改变默认解释器指纹；所有路径配置在本轮验收期间保持不变。
2. 选择本人已有、结构可读且含至少三段带足够原片余量的简单工程作为**只读源**。未知资源、多时间线或复杂剪辑先停止。脚本保留原稿与配置指纹，不修改它们。
3. 本机测试需要已存在的叠化及闪白资源；缺少／付费／未验证则停止，不自动下载、自动替换或绕过权限。配置文件必须真实存在（即便本轮不注册），用于保护指纹。

## A. 初始原片引用与增量副本

```powershell
py -3.12 -I -B -X utf8 .\scripts\jianying_local\prepare_canaries.py --config .\config.local.json --source-draft '<your-readable-draft-directory-name>'
```

此显式测试入口使用 `--canary` 内部模式，生产 MCP 不开放该开关。生成 A 短草稿、B 增量副本、技术提示音和 `work_root/canaries.json`；原片不复制。手动打开、播放、检查入出点与前后延长，再撤销测试拖拽；B 检查新增音轨／音量变化／转场。保存、重开、退出。音轨可见不是实际试听，提示音不是正式发布 BGM。

## B. 五组扩展验收

```powershell
py -3.12 -I -B -X utf8 .\scripts\jianying_local\prepare_phase2.py --config .\config.local.json
```

从本次 A/B 读最新保存状态。输出精确名称、有效时间及 `acceptance_checklist_phase2*.md`，以生成的清单为准，不依赖此文档的概略数字。

1. **最新保存状态**：打开01，第一段原声音量在剪映改成 **−3.1 dB**，其他不改，保存、退出、重开。后台必须读回真实浮点线性值，而不是旧根 JSON。
2. **局部修改／联动／字幕**：02的局部插入、调序和延长符合计划，未重铺；提示音联动符合范围。时间轴 SRT、重复原片 SRT 每次使用位置及跨界整句可追溯，底部文字可编辑。
3. **配乐／新增转场**：03循环末段、交叉淡化、明确区间避让、淡入淡出实际试听无明显异常；指定切点闪白可见。保持旧内容，保存重开。
4. **安全重链接**：04合成图案能播放，不丢素材。只有脚本新建的极小合成素材搬迁；辅助旧失效路径草稿仅作证据，不修改用户媒体。
5. **竖屏字幕**：05中文在底部，字号／描边／安全区合适，点击可编辑，保存重开保留。

全部保存并彻底退出后填写本次生成的 `human_report_phase2_template*.json`。其检查默认 **false**；只有实际完成的对应项才改 true。`user_confirmation` 记录真实用户确认或真实委托验收证据，不让工具生成“通过”。`manifest_path` 已指向本次清单。

```powershell
py -3.12 -I -B -X utf8 .\scripts\jianying_local\acceptance_phase2.py '<completed-local-report.json>' --config .\config.local.json
py -3.12 -I -B -X utf8 .\scripts\jianying_local\cli.py doctor --config .\config.local.json
```

录入器重新解析最新保存稿，检查手工音量变化、五组内容、保存规范化、原稿／媒体／索引条目和配置边界，通过才生成本机 `native_acceptance.json`。不是只勾选报告就通过。失败时保留诊断和草稿，不伪造门禁；报告、验收与快照永远不上传公开仓库。

### 双明文源的额外副本检查

若生产源是 `flat-mirrored-360000`，另选本人两个内容文件字节一致的可读草稿，在显式授权的 CLI `--canary` 测试中生成小型增补副本；不能为了通过识别而复制／重命名旧文件来伪装双明文。检查底部字幕、实际本地配乐与指定叠化，打开、播放、保存、重开、退出，并确认只读源的两个文件均未变。

本次人工报告额外填写 `mirrored_copy_evidence`：准确的 `name`、本次 `plan_id`、真实 `actor`（`user` 或 `delegated_agent`）、`opened_played_saved_reopened` 和具体 `observations`。录入器核对计划的 canary／格式／代码指纹、输出副本和最新原生读回；这些字段不是 MCP 工具参数。该项未通过时双明文生产写入保持关闭。存在旧验收记录时保留为历史证据，不能只修改代码指纹、检查勾选或资源来升级为新构建通过。

## C. MCP 验收

按 [安装说明](install.md) 安装独立 SDK，完成真实只读 smoke 及 `smoke_mcp.py` 的独立副本写入。用户再手工播放、保存、重开 MCP 特定副本；文件校验与人工试听分别记录。最后才显式注册。

源码、路径、配置、后端、剪映或 codec 指纹变化可能使验收失效。原生测试通过仅证明这一本机配置，不开放任意版本，不让 CI 替代播放／试听，也不代表音乐发布授权。
